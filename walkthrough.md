## 3. Temel Veri Modeli

### Directorate (Direktörlük)
- `id`, `name` (unique), `code`, `gmy`, `isActive`
- Kontrol, Bulgu, Aksiyon ve Takip Çalışmalarına FK ile bağlı
- `GET/POST/PUT /directorates` endpoint'leri

### Control (Kontrol)
- `controlId`: `C-YYYY-XXXX` formatı
- `directorateId`: FK → Directorate
- `frequency`: DAILY/WEEKLY/MONTHLY/QUARTERLY/SEMI_ANNUAL/ANNUAL/AD_HOC
- `selectedMonths`: Periyodik kontroller için seçili aylar
- Aktif edilince → `generateTestsForControl()` otomatik test üretir

### ControlTest (Kontrol Testi) — *eski TestRecord absorbe edildi*
- `testNo`: `T-YYYY-XXXX` formatı
- `status`: BEKLIYOR → DEVAM_EDIYOR → TAMAMLANDI → ONAYLANDI
- `findingStatus`: BULGUSU_YOK / BULGUSU_VAR
- `isAutoGenerated`: Otomatik mi, manuel mi?
- `findings Finding[]`: Doğrudan bulgu ilişkisi

### Finding (Bulgu)
- `findingId`: `YYYY.BT.XX` veya `YYYY.İB.XX` formatı
- `workflowStatus`: TASLAK → MUTABAKATA_GONDERILDI → IC_KONTROL_ONAYINA_GONDERILDI → MUTABAKAT_YAPILDI → IPTAL
- `resolutionStatus`: DEVAM_EDIYOR / KISMEN_KAPATILDI / KAPATILDI / ERTELENDI / YENI_AKSIYON_GEREKLI
- `targetResolutionDate`: **Hesaplamalı** — açık aksiyonların MAX(dueDate)
- `controlTestId`: FK → ControlTest (nereden tespit edildi?)
- `directorateId`: FK → Directorate

### Action (Düzeltici Aksiyon)
- `actionId`: `A-YYYY-XXXX` formatı
- `findingId`: Her aksiyon mutlaka bir bulguya bağlı
- `directorateId`: FK → Directorate
- Oluşturulunca → `autoCreateFollowUpForAction()` otomatik takip çalışması oluşturur

### FindingFollowUp (Bulgu Takip Çalışması)
- `followUpId`: `FU-YYYY-MM-XXXX` formatı
- `result`: YETERLI / YETERSIZ / YENI_AKSIYON_GEREKLI
- `resolutionOutcome`: Ana bulgunun çözüm durumunu günceller
- `currentStatusDetail`: Ana bulguda append-only log'a eklenir
- `directorateId`: FK → Directorate

### Attachment (Polimorfik Ek Dosya)
- Tek tablo: `entityType` (CONTROL/CONTROL_TEST/FINDING/CORRECTIVE_ACTION/FINDING_FOLLOW_UP) + `entityId`
- Şimdilik metadata (fileName, mimeType, sizeBytes) — gerçek upload sonraki sprint

### FindingStatusHistory (Audit Trail)
- Tüm kritik işlemler kaydedilir
- `operation`: FINDING_CREATED, ACTION_ADDED, FOLLOWUP_COMPLETED, WORKFLOW_CHANGE...
- `oldValue` / `newValue`: JSON olarak eski/yeni değerler
- `userId`: İşlemi yapan kullanıcı

## 4. API Endpoint Referansı

### Directorates
```
GET    /directorates              # Liste (isActive filtresi)
GET    /directorates/:id          # Detay
POST   /directorates              # Oluştur (Manager+)
PUT    /directorates/:id          # Güncelle (Manager+)
DELETE /directorates/:id          # Pasifleştir (Admin)
```

### Controls
```
GET    /controls                  # Liste (status, directorateId filtresi)
GET    /controls/:id              # Detay (tests, findings dahil)
POST   /controls                  # Oluştur
PUT    /controls/:id              # Güncelle
PATCH  /controls/:id/activate     # Aktif et → testler otomatik oluşur
PATCH  /controls/:id/passivate    # Pasif et
DELETE /controls/:id              # Sil
```

### ControlTests
```
GET    /controls/tests            # Tüm testler (status/directorateId/findingStatus filtresi)
GET    /controls/:id/tests        # Kontrol bazlı testler
POST   /controls/:id/tests        # Manuel test oluştur
POST   /controls/:id/generate-tests  # Otomatik test oluştur
PATCH  /controls/tests/:id/start      # Başlat (BEKLIYOR → DEVAM_EDIYOR)
PATCH  /controls/tests/:id/complete   # Tamamla + findingStatus gir
PATCH  /controls/tests/:id/approve    # Onayla (TAMAMLANDI → ONAYLANDI)
PATCH  /controls/tests/:id/return     # Geri gönder + gerekçe
```

### Findings
```
GET    /findings                  # Liste
GET    /findings/:id              # Detay (actions, followUps, attachments, statusLogs)
POST   /findings                  # Oluştur
PUT    /findings/:id              # Güncelle
DELETE /findings/:id              # Sil

# Mutabakat Akışı
POST   /findings/:id/workflow/mutabakata-gonder
POST   /findings/:id/workflow/ic-kontrol-onayina-gonder
POST   /findings/:id/workflow/mutabakat-onayla
POST   /findings/:id/workflow/mutabakat-geri-gonder
POST   /findings/:id/workflow/iptal-et

# İlişkiler
POST   /findings/:id/link-risk
DELETE /findings/:id/unlink-risk/:riskId

# Aksiyonlar
GET    /findings/:id/actions
POST   /findings/:id/actions
PUT    /findings/:id/actions/:actionId
DELETE /findings/:id/actions/:actionId

# Takip Çalışmaları
GET    /findings/:id/follow-ups
POST   /findings/:id/follow-ups
PUT    /findings/:id/follow-ups/:followUpId

# Status Logs (Append-only)
GET    /findings/:id/status-logs
POST   /findings/:id/status-logs

# Audit Trail
GET    /findings/:id/status-history

# Ekler
POST   /findings/:id/attachments
DELETE /findings/:id/attachments/:attachmentId
POST   /findings/:id/actions/:actionId/attachments
POST   /findings/:id/follow-ups/:followUpId/attachments
```

### Follow-Ups (Bağımsız Liste)
```
GET    /follow-ups                # Tüm takip çalışmaları (status/month/year filtresi)
```
